Over the years I've come to the conclution that my
work flow works best mantaining with tools that do
specific tasks. This to know all the ins and outs
of the stacks im using.

The main pilars for building or using new tools
are the following:

1. Small
2. Specific
3. Extensible

Some times there are exceptions since while
working I'm expected to quickly create leaving
these pilars behind. But for personal projects I
aim to keep this philosophy.

## Personal

Personally I'm one of those people that uses
thinkpads and for a good reason. These laptops are
cheap, resistant and I've never needed anything
other than a thinkpad. Great machines.

I got 2 thinkpads, one being my main station being
a Thinkpad X1 carbon Gen 8 from 2020 for intensive
tasks such as running VMs or developing for
Android. And a older Thinkpad 3680 with OpenBSD
for tinkering with software the old fashioned way.


### Thinkpad Carbon X1 Gen 8
* Operating System: Arch Linux

Honestly I would love to use OpenBSD as a daily
driver but there are caveats to this. OpenBSD is
slow for and lacks a lot of support for most of
the tools I use. I know there are options but this
is a sacrifice in my developer performance I
already accepted. This said, I've never found
myself in a position that Arch Linux screwed a
project, tool or package being reliable and
customizable.

Been using Arch since 2020.

* Text Editor: Neovim
VimKeys are GOATED, period. Emacs is the only
editor that is near to the perfection to vim but
the problem in workflow is that it makes you want
to use more and more, interfering with my 3 pilars
for workflow. NeoVim kind of forces me to keep
things small and I see this as a win.

I know my setup is far from small, specific and
extensible. But at least you are unable to tun an
entire OS in it. hahahaha.

exactly the case. Firefox is trash but it's the
